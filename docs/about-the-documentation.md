# Documentation Guidelines

### Purpose

This documentation records the engineering thought process behind building this project. It captures the reasoning, design decisions, implementation approaches, and the evolution of the project instead of documenting only the final outcome.

### Objectives

This documentation aims to:

* Explain what is being built.
* Explain why a particular design or implementation was chosen.
* Explain how the application is implemented.
* Preserve the evolution of the project.
* Record the reasoning and thought process throughout development.

### Intended Audience

This documentation is primarily written for:

* **Myself**, to revisit design decisions, understand the project after a break, and assist in debugging or future modifications.
* **Future Contributors**, to understand the project's architecture and implementation before extending it.
* **Future LLMs**, to provide complete context about the project's design and evolution, making future development or rebuilding easier.
